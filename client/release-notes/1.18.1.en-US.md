Looklook desktop 1.18.1: when a remote session can't connect, you now see why, and relay latency is measured on the path the connection actually uses.

- When the remote console can't connect, the page and the desktop app explain which side's network is the problem (for example, UDP blocked on your network) instead of just "channel open timeout"
- Relay latency in the relay list is now measured over UDP against the relay's TURN service, matching the path remote connections take; "Can't connect (UDP blocked)" means UDP from this network to that relay doesn't get through
