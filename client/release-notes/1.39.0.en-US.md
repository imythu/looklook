LookLook desktop 1.39.0: direct connections when you have a public address or port forwarding, and packet loss in the connection status.

- New: Settings → Network → Direct connection lets you set the WebRTC port range (default 50000–50031) and this computer's public IPv4 / IPv6 address (either one is enough). Forward that UDP range on your router to this computer, port for port, and phones and other computers can connect directly instead of going through a relay. If every port in the range is taken, a random port is used.
- New: the Detect button asks a few public services for this computer's public address to help you fill it in; you decide whether to use it. If the address you entered can't be reached, the connection falls back to a relay automatically.
- New: on computers without a screen (such as Linux servers) use the command line: `looklook rtc ports 50000-50031`, `looklook rtc ipv4 <address>`, `looklook rtc ipv6 <address>`, `looklook rtc detect --apply`; run `looklook rtc` to see the current settings.
- Improved: a public IPv6 address is tried first for direct connections.
- New: the connection status shows packet loss next to latency; it turns orange when loss is high and red when it is very high.
- Improved: on phones, the connection details no longer run off the left edge of the screen, and the computer menu shows each computer's path, packet loss and address under its name, without hovering.
